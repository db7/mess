    [1;91m[0m[1;91mmess [0m[1;91m–[0m[1;91m more or less with links[0m
    
    [1;94mmess[0m a wrapper program that adds link navigation support to pagers,
    eg, [1;94mless[0m. It watches the output of the underlying pager for ]8;;https://gist.github.com/egmontkob/eb114294efbcd5adb1944c9f3cb5feda\[1;93mOSC8[0m]8;;\
    ]8;;https://gist.github.com/egmontkob/eb114294efbcd5adb1944c9f3cb5feda\[1;93msequences[0m]8;;\ and lets you tab through the links.
    
    [1;94mmess[0m relies on external tools such as [1;94mless[0m, ]8;;https://lynx.browser.org/\[1;93mlynx[0m]8;;\, and ]8;;https://kristaps.bsd.lv/lowdown/\[1;93mlowdown[0m]8;;\, and
    targets POSIX environments (macOS, the BSDs, Linux) where standard
    utilities like [1;94mman[0m, [1;94mless[0m, and [1;94mwordexp(3)[0m are available.
    
    Usage:
    
    [1;94m  │ [0m[1mmess [less-args]          # run the pager wrapper[0m
    [1;94m  │ [0m[1mmess --open <url>         # launch a link using the helper[0m
    [1;94m  │ [0m[1mmess --version            # show the current version[0m
    [1;94m  │ [0m[1mmess --open man://ls.1    # look up ls(1) and page it with navigation[0m
    [1;94m  │ [0m[1mmess -m                   # force stdin to be parsed as a man page[0m
    
    When the input is a man page (e.g. a [1;94mfoo.1[0m file, [1;94mman://[0m link, or
    the output of [1;94mman -P cat[0m), [1;94mmess[0m scans the rendered text for
    references such as [1;94mprintf(3)[0m or [1;94msocket(2)[0m and exposes them as
    navigation targets. Press [1;94mTab[0m to highlight those tokens and [1;94mEnter[0m
    to jump via the new [1;94mman://[0m helper. Combine this with [1;94mMANPAGER='mess[0m
    [1;94m-m'[0m when you want [1;94mman[0m to feed directly into mess’s manual-aware
    navigation.
    
    See [1;94mmess.1[0m for a complete reference, including details on the [1;94mPAGER[0m
    and [1;94mBROWSER[0m environment variables that let you choose the pager and
    link opener. While the pager is active, press [1;94mv[0m to open the current
    document in your [1;94m$VISUAL[0m or [1;94m$EDITOR[0m (falling back to [1;94mvi[0m) before
    returning to the pager. The file passed to the editor comes from
    the [1;94mMESSFILE[0m environment variable: the dispatcher ([1;94mmess[0m
    [1;94m<file-or-uri>[0m) sets it automatically, and wrapper mode ([1;94m... | mess[0m)
    can opt in by exporting [1;94mMESSFILE[0m before launching the pager.
    
    [1;36m### [0m[1;36mTesting[0m
    
    To build [1;94mmess[0m and perform unit and integration tests, run:
    
    [1;94m  │ [0m[1mmake test[0m
    
    The integration suite drives a pseudo-terminal to ensure the pager
    restores the original terminal settings and handles window resizes.
    Some sandboxes require running [1;94mmake test[0m with elevated permissions
    so the PTY can become the controlling terminal.
    
    [1;36m### [0m[1;36mExit behaviour[0m
    
    When piping something like [1;94mlowdown --term ... | mess[0m, the program
    exits in a few predictable ways:
    
    [93m  · [0mquitting the pager (pressing [1;94mq[0m in [1;94mless[0m) — normal exit; 
    [93m  · [0mthe input stream finishes — upstream closes the pipe and [1;94mless[0m
        exits; 
    [93m  · [0mpressing [1;94mCtrl-C[0m once — the loop stops and waits for [1;94mless[0m;
        pressing it again before the child exits forces [1;94mmess[0m to abort
        with status 1; 
    [93m  · [0mthe pager fails to launch ([1;94mexecvp("less", ...)[0m or missing tool)
        — error exit; 
    [93m  · [0mcritical system or I/O errors (PTY setup, [1;94mselect[0m, [1;94mread[0m, [1;94mwrite[0m,
        etc.) — error exit; 
    [93m  · [0mwriting processed output fails (e.g. downstream terminal
        disappears) — error exit. 
    
    [1;36m## [0m[1;36mDesign[0m
    
    [1;94mmess[0m forwards all arguments and piped input to a spawned pager
    process ([1;94mless[0m by default). The output the pager is parsed for OSC8
    links and are kept in an array. The keyboard input is also
    forwarded to the pager unless [1;94m<TAB>[0m or [1;94m<S-TAB>[0m are pressed. In that
    case, [1;94mmess[0m enters in navigation mode. It keeps an index in the
    array of parsed links. The link at the current index is shown at
    the last terminal line. Using [1;94m<TAB>[0m/[1;94mj[0m and [1;94m<S-TAB>[0m/[1;94mk[0m the user can
    rotate over the stored links. Pressing [1;94m<ENTER>[0m (or [1;94mEsc[0m/[1;94mCtrl-L[0m to
    exit without launching) spawns an external helper (]8;;https://lynx.browser.org/\[1;93mlynx[0m]8;;\, ]8;;https://kristaps.bsd.lv/lowdown/\[1;93mlowdown[0m]8;;\,
    etc.) with the given URL. The parent process listens for [1;94mSIGWINCH[0m,
    mirrors the new dimensions onto the child PTY, and forwards the
    signal so the pager keeps its layout in sync with your terminal.
    
    Press [1;94mD[0m at any time to toggle a debugging overlay that lists the
    stored links and their targets; this is handy when tuning markup
    that emits OSC8 sequences or manual cross references. Press [1;94mc[0m to
    colorize every detected link inline, making it easier to spot which
    targets [1;94mmess[0m currently tracks, and press [1;94mx[0m to toggle the one-second
    “freeze” window that starts the first time you hit [1;94mTab[0m. While the
    freeze toggle is on (the default), the pager redraw is captured for
    one second and then the screen stays put; a highlighted [1;94mmessF[0m
    marker on the top-right corner reminds you when navigation is
    active, and a trailing [1;94m![0m appears whenever fresh pager output was
    suppressed.
    
    [1;36m### [0m[1;36mOff-screen snapshots[0m
    
    The experimental [1;94moffscr[0m component provides an isolated helper for
    capturing child PTY output into an in-memory snapshot that other
    subsystems can inspect. It is not wired into the pager yet, but the
    public interface is ready for integration:
    
    [1;94m  │ [0m[1mstruct offscr_ctx *offscr_new(const struct offscr_opts *);[0m
    [1;94m  │ [0m[1mint offscr_capture(struct offscr_ctx *, int child_fd);[0m
    [1;94m  │ [0m[1mvoid offscr_reset(struct offscr_ctx *);[0m
    [1;94m  │ [0m[1mstruct offscr_view offscr_view(const struct offscr_ctx *);[0m
    [1;94m  │ [0m[1mvoid offscr_free(struct offscr_ctx *);[0m
    
    [1;94moffscr_capture()[0m reads from [1;94mchild_fd[0m until the stream becomes idle
    or the configured limit is reached. The snapshot can then be
    processed by navigation logic without juggling file descriptors.
    Set [1;94mmax_lines[0m in [1;94moffscr_opts[0m if you want to stop after a certain
    number of newline-terminated rows (leave it zero to capture the
    full stream), and tune [1;94mfirst_byte_timeout_ms[0m / [1;94mnext_byte_timeout_ms[0m
    to control how long the capture waits for initial vs. subsequent
    bytes (defaults: 1000 ms and 250 ms respectively, zero blocks
    indefinitely). Flip [1;94mdrain[0m to true when you only need to
    consume PTY output without keeping a snapshot (e.g. before sending
    commands). See [1;94mtests/tes-offscr.c[0m for usage examples and
    expectations around timeouts/truncation, and [1;94mtests/test-styler.c[0m
    for styling helpers.
    
    [1;36m### [0m[1;36mEnvironment[0m
    
    [93m  · [0m[1;94mPAGER[0m / [1;94mMESSPAGER[0m select which pager [1;94mmess[0m spawns when acting as
        a wrapper; [1;94mless -R[0m is the default fallback. When you export [0m
        [1;94mPAGER=mess[0m system-wide, set [1;94mMESSPAGER[0m to your real pager (e.g. [0m
        [1;94mless -R[0m) so the dispatcher knows what to run downstream. 
    [93m  · [0m[1;94mBROWSER[0m controls how external links ([1;94mhttps://[0m, [1;94mfile://[0m, etc.)
        are opened by the dispatcher, defaulting to [1;94mopen[0m on macOS and [0m
        [1;94mxdg-open[0m elsewhere. 
    [93m  · [0m[1;94mVISUAL[0m / [1;94mEDITOR[0m provide the command invoked when you press [1;94mv[0m;
        if neither is set [1;94mvi[0m is used. 
    [93m  · [0m[1;94mMANPAGER[0m is set to [1;94mmess -m[0m automatically when dispatching [0m
        [1;94mman://[0m URIs or [1;94m.1[0m files so manual links keep navigation
        support, but you can override it if you prefer a different
        pager wrapper. 
    [93m  · [0m[1;94mMESS_MDRENDER[0m overrides the Markdown renderer command. By
        default [1;94mmess[0m runs [1;94mlowdown -tterm --term-no-links <file>[0m and
        pipes the result into the pager; point this variable at another
        program (e.g. [1;94mpandoc -t plain[0m) to customise the conversion. 
    [93m  · [0m[1;94mMESSFILE[0m identifies the document currently shown in the pager.
        The dispatcher sets it before spawning downstream programs so
        the [1;94mv[0m shortcut knows which file to edit. When feeding [1;94mmess[0m via
        stdin directly, export [1;94mMESSFILE=/path/to/file[0m yourself so the
        editor shortcut has context. 
    [93m  · [0m[1;94mMESS_DEBUG_STATUS[0m can point to a file path when you want to
        trace the raw bytes written to the status line while developing
        or debugging the navigation overlay.
